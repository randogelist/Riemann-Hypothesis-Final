The expected first run can reuse the 84 old ordinary modules from validated
shared anchors, then compile five inherited analytic candidates and the
aggregate. If these are already validly cached, they can also be reused.
All reuse is decided by the existing fresh-content and same-target audits.
New versioned workspaces may first restore artifacts before retaining them.

After the old imports are accepted, CanonicalPowerSums, SpectralPhase and
SpectralGenerating can run together. Extraction waits for both spectral
modules; AnalyticClosure joins extraction and power sums. AnalyticAudit runs
last. Each dependent waits for its imports' completed audit and acceptance.

AUTO warming is attempted only for a dirty ordinary-module frontier of two
or more jobs and only with an available RAM budget. Fully cached runs skip
it. Set RH_RAM_WARM=OFF to compare parallel runs without the warmer.
Set RH_MODULE_WORKERS=1 as well for serial admission in this new runner.

A Lean thread budget is not a limit on every Windows thread/process. When
parallel workers are configured, one thread token is reserved and the
remaining 15 default tokens are divided among Lean tasks. Final audit uses 16.
Memory admission estimates are conservative, not hard memory limits.

The optional read-only x64 warmer uses the existing .NET Framework csc.
It does not install anything, change compiler flags, or authorize cache reuse.
The SHA256 helper source and proof cache acceptance functions are unchanged.
Hashing can already warm the file cache; performance must be measured locally.

Node mocks do not exercise COM, WMI, real process trees, native page mapping,
compiler behavior or native speed. See README and runtime evidence for scope.
